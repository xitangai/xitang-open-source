# 发布与恢复

## 本机记录与查重

本地运行资料默认放在当前用户主目录的 `.xys-feishu-to-x/`，按实际 X 账号和原文标识分开。用当前系统的主目录解析能力取得路径，不写死用户名、操作系统盘符或某位成员的电脑路径；已有任务目录可复用，并在索引中保存其位置。

```text
.xys-feishu-to-x/
  account-key/
    source-key/
      result.json
      source-snapshot.*
      article.*
      media-manifest.json
      media/              有素材时创建
```

`account-key` 使用实际核对的账号标识，`source-key` 优先使用规范化 docx token；只取得 Wiki URL 时可用规范化 URL 的哈希作为临时键，记录别名并在解析成功后关联。不要猜 Wiki/docx 映射，也不要按标题生成唯一键。用户改过账号名时结合已知主页、公开链接和记录核对身份，不把旧用户名直接当别人的账号。

记录仅留本机，正文、原文链接和素材不放进共享 Skill 文件夹或团队分发包。支持时将运行目录和文件限制为当前用户可读写。浏览器登录由浏览器管理，记录中不保存密码、Cookie 或令牌。

首次开始及中断恢复都先读记录，再核对当前账号主页／Articles 中是否已发同文。X 文章通常不含飞书链接，需要结合标题、独特开头、作品名、关键媒体等识别；不能只搜索原链接。新标题、不同来源地址或本地没有记录，都不证明从未发过。

同一文章发在另一个账号，不直接当成本账号重复；历史记录里的账号必须与本次目标对应。若本机有其他工具的相关发布记录，可以核对其 X 结果，不改动那些工具的状态。已发表文章的修订或重发须有相应用户要求，不能自动删除重发。

## 状态与恢复

`result.json` 至少保存：目标账号、来源 URL 和别名、原文标识、状态、最终稿路径、草稿 URL（如有）、媒体进度、已取得的公开 URL、提交与核验时间。引用截图或回读记录即可，不强求一套大日志。

| 状态 | 恢复方式 |
| --- | --- |
| `preparing` | 读取已取得的原文与素材，确认版本后继续整理。 |
| `local_draft` | 用户只要看稿或平台不具备发布能力；没有上传或提交。 |
| `platform_draft` | 打开实际草稿回读，核对已保存文字和媒体，再继续。 |
| `submitting` | 最终发表前已记录；恢复时先查结果，查明之前不能再提交。 |
| `published_verified` | 已有真实公开页并完成内容核验，返回原链接。 |
| `published_unverified` | 已确认公开，但正文／媒体回查尚未完成；继续核验原帖，不再发。 |
| `unknown` | 已尝试提交但无法确定结果；先查平台，仍不明确则报告待核查。 |

每次重要进度更新前重读当前记录，保留已有字段，用临时文件原子替换，避免断线留下半份 JSON。确认另一个任务正在处理同一账号同一原文时不要并行发表；已有草稿不必从头重建，恢复进度以实际页面为准。

发布前写入 `submitting`、时间、当前账号及最终稿快照，再执行一次最终提交。一次搜索没有结果、一次超时或仅看到编辑器，都不足以允许重发。有明确证据证明未提交（例如平台明确返回发表前的校验失败），且已核对同一草稿和发布状态时，可以修复后继续；实际状态不明先回查。

## 编辑器操作

使用当前会话提供的正常浏览器工具，按其文档初始化、读取当前页面和上传说明；不硬编码旧元素序号、DOM 选择器、内部接口或已失效的工具 API。使用正常的页面输入、剪贴板和文件选择能力，不用 DOM 写入伪造编辑器保存。

1. **账号与能力**：依据真实登录信息核对目标，检查 Articles 是否可编辑和发表。正文、配图尚未准备好时不要点最终提交；无权益时不购买、不自动降级为删减版。
2. **文字**：标题单独填入；正文可用语义 HTML 经工具支持的剪贴板正常粘贴，再读回实际渲染。原生段落已有间距，不额外添加空段。长提示词保留完整文字和有意义的换行。
3. **素材**：HTML 中的本地路径或飞书私有链接不能替代上传。逐项定位并上传真实文件，等待处理和自动保存完成，核对媒体内容、顺序、前后段落，再处理下一项。
4. **插入位置**：若使用临时媒体标记，确认选中完整标记且删后位置正确再上传。曾出现新媒体插到前一个块旁的情况；保存提示不足以证明位置正确，发现错位先修正，不连续盲传或反复撤销。
5. **续做**：工具超时后先查看文件是否已经上传。重新加载前确认保存完成，记录草稿地址和已完成素材，避免重传或丢失内容。

正文改动后重新检查受影响部分；只修改媒体位置时，不必重写整篇文章。浏览器工具或平台强制要求的授权须正常处理，不绕过限制。

## 验收

发表前逐段比对最终稿与编辑器，不只比较字数；按清单核对封面和正文媒体，不只比较总数量。实际查看文章开头、提示词、媒体衔接和结尾，检查裁切、空白、标题层级、署名与披露，去掉内部标记和本地路径。

发布后从页面取得真实公开链接，打开详情并滚动加载全文。回查当前账号、标题、全文、完整提示词、全部对应媒体和页面显示的发布时间。图片应能加载，关键视频实际播放；无法完成的核验如实记录。编辑 URL、预览或一个成功提示不能作为完整验收。

账号权益和上传限制以当前编辑器及必要的官方说明为准，不写死某位成员的媒体配额。仅在本次需要时查：

- 视频上传：https://help.x.com/en/using-x/x-videos
- 图片与 GIF：https://help.x.com/en/using-x/posting-gifs-and-pictures
- 普通帖字符计数：https://docs.x.com/fundamentals/counting-characters
- 商业合作披露：https://help.x.com/en/rules-and-policies/paid-partnerships-policy

用户明确要普通帖时核对平台当前的加权字符限制，不能把中文字符数当精确计数。完整 Articles 不套普通帖长度，也不静默截断。
