# 飞书文章发推特

名称：`xys-feishu-to-x`

给 Codex 一个自己的飞书文章链接，让它读取全文和素材，自主判断是否需要轻改写，然后发布到本机登录的 X 账号，并返回真实帖子链接。

## 安装到成员自己的 Codex

解压分发包，把包含 `SKILL.md`、`agents/` 和 `references/` 的整个 `xys-feishu-to-x` 文件夹交给 Codex，并说：

```text
请把这个 xys-feishu-to-x 文件夹安装成我的个人 Codex Skill，检查本机可用的 Skill 目录，保留已有 Skill。安装完成后检查能否找到“飞书文章发推特”。本次只安装，不发布文章。
```

当前官方文档列出的用户级目录是 `~/.agents/skills/`；部分现有环境也使用 `~/.codex/skills/`。安装时以本机已识别的目录和工具说明为准，只装一份，不在多个扫描目录复制同名 Skill。Codex 会检测 Skill 变更；如果未显示，可重新启动后再检查。参见 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills)。

## 使用前准备

- 在成员自己的电脑上使用 Codex，并在浏览器登录自己的飞书和 X 账号。
- 当前 Codex 会话需要有能操作该浏览器、支持文件上传的工具。Skill 是操作流程，不自带浏览器工具、账号或登录状态；让 Codex 检查当前能力即可，不必照搬他人的环境配置。
- 飞书文章需要当前账号有阅读及相应素材访问权限。完整文章发布还需要该 X 账号具备 Articles 能力，运行时会检查。
- 不需要提供密码、Cookie，也不用预先填写作者人设或账号配置文件。需要登录时按页面由本人完成。

## 日常使用

```text
使用 $xys-feishu-to-x，把这篇飞书文章整理后直接发布到我的推特：
【粘贴飞书链接】
```

也可以说「把这个飞书链接里的内容发到我的推特」。Codex 会先说明当前目标账号，再读取、判断改写、排版和上传，检查通过后直接发布，无需逐步指挥或再次批准稿件。

想先看稿：

```text
使用 $xys-feishu-to-x 处理这个飞书链接，先给我看稿，不发布：
【粘贴飞书链接】
```

这一模式只生成本地稿件，不上传到 X。如果希望保存到平台草稿，可明确说「整理后存到 X 草稿，暂不发布」。

## 结果与中断

正常完成后得到发布状态、真实帖子链接，以及正文和素材检查结果。网络、权限或上传出现问题时，Codex 会保留进度并说明具体卡点；处理后在同一对话说「继续刚才的发布」，先回查已有状态，避免重传或重复发帖。

该 Skill 默认只处理本次文章，不修改飞书正文或分享权限，不购买账号权益。安装与静态检查通过，不等于所有成员的登录、上传和发布环境都已实测。
